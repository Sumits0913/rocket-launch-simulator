## 0. 双模式的共通基础

**两套模式跑的是同一套物理内核、同一份参数表。** 差异只在**控制层**与**表现层**，不在物理层。

```
┌─────────────────────────────────────────┐
│          物理内核（唯一，不可分叉）          │
│   physics.md 的运动方程 + vehicle.md 参数   │
└──────────────┬──────────────────────────┘
               │
      ┌────────┴────────┐
      ▼                 ▼
┌───────────┐     ┌───────────┐
│ 演示模式   │     │ 挑战模式   │
│ 脚本引擎   │     │ 引导+评分  │
│ 教师控制   │     │ 玩家控制   │
│ 强制 AP    │     │ AP+bias   │
│ 禁用失败   │     │ 启用失败   │
└───────────┘     └───────────┘
```

| 维度 | 演示模式 | 挑战模式 |
|---|---|---|
| 目标用户 | 教师（大屏讲解） | 学生（独立操作） |
| 姿态控制 | **纯 AP**（玩家输入禁用） | AP + bias，可切全手动 |
| 失败判定 | **全部禁用** | 全部启用 |
| 时间控制 | 暂停 / 慢放 / 节点跳转 / 加速 | 加速 / 暂停（无跳转、无慢放） |
| 数据层 | 教师可控（L0–L3） | 玩家可控（精简 / 完整 / 核验） |
| 目标 | 稳定可复现、讲解节奏 | 引导、容错、成就、评分 |
| 一次时长 | 约 10–13 分钟（含讲解） | 约 5–12 分钟（取决于加速档） |

## 1. 演示模式

### 1.1 设计原则

| 原则 | 说明 |
|---|---|
| **绝不翻车** | 教师在大屏前，最坏的结果是"演示失败"。演示模式禁用全部失败判定，且保证达成入轨 |
| **随时可停** | 教师随时会被打断提问。任何时刻可暂停，暂停时数据冻结且可展开查看 |
| **随时可跳** | 教师可能只想讲 Max-Q 或入轨。支持按节点跳转 |
| **不干扰** | 无弹窗、无成就提示、无评分面板。所有信息常驻或按需展开 |
| **讲得清** | 字幕区 + 事件高亮 + 数据面板三层配合 |

### 1.2 教师控制清单

| 控制 | 按键 | 鼠标 | 说明 |
|---|---|---|---|
| **播放 / 暂停** | `空格` | 底部控制条 ▶/⏸ | 暂停时数据冻结，展开面板可查看任意数值 |
| **上一节点 / 下一节点** | `←` / `→` | 点击时间轴节点 | 跳转到 `mission-profile.md` §1 的 E0–E12 节点 |
| **调速** | `↑` / `↓` | 速度档按钮 | 档位：**0.25× / 0.5× / 1× / 2× / 5× / 10×** |
| **数据层切换** | `D` | 右上角层按钮 | **L0 纯净 / L1 标准 / L2 完整 / L3 核验**，循环切换 |
| **相机切换** | `C` | — | 跟随 / 全景 / 轨道俯视（3 档循环） |
| **重播当前段** | `R` | — | 回到上一节点重播 |
| **讲解字幕开关** | `S` | — | 开 / 关 |
| **返回模式选择** | `Esc` | 左上角返回 | |
| **跳转到任意时刻** | — | 拖动时间轴 | 支持任意时刻（非仅节点） |

**关键交互：节点跳转的实现要求**
- 节点跳转 = 恢复该节点的**状态快照**（`mission-profile.md` §5.2 机制）+ 重置后续累加器。
- 跳转后自动暂停，等教师按空格继续。
- 时间轴上标出 12 个节点图标，当前节点高亮，鼠标悬停显示节点名（"助推分离"）。

### 1.3 数据层（Data Layer）—— 演示模式的核心创新

教师面对不同年龄段、不同课时长度，需要的信息密度完全不同。

| 层 | 名称 | 显示内容 | 适用场景 |
|---|---|---|---|
| **L0** | **纯净** | 火箭主视图 + 速度 + 高度 + 任务时间 + 事件进度条。**无侧栏、无曲线** | 小学生；第一次观看；只想看"热闹" |
| **L1** | **标准** | L0 + 推进剂条 + 动压读数 + 当前事件名 | 初中生；常规教学 |
| **L2** | **完整** | L1 + 侧栏（Δv 预算表 + 轨道根数 + 4 条实时曲线） | 高中生/社团；讲原理 |
| **L3** | **核验** | L2 + 参数来源标签 + Δv 恒等式残差 + 三级满载交叉验证 | 答疑环节；回应"这数据是真的吗" |

**默认层：L1（标准）。** 层状态在演示过程中可随时切换，不影响仿真。

**实现要求**：每一层的元素在 DOM/SVG 中预先存在，用 CSS 类控制显隐，避免切换时重排导致的画面跳动。

| **E1 起飞** | — | "起飞推重比只有 1.224。前 10 秒几乎没有速度感——真实运载火箭都这样起飞。" | 加速度 |
| **E2 转弯** | — | "开始重力转弯。注意：入轨需要的不是高度，是**每秒 7.8 公里的横向速度**。" | 弹道倾角 γ |

| **E8 二级关机** | ★ 1× | "二级烧完。速度 7.15 公里每秒，高度 189 公里，几乎平着飞了。但还不够——圆轨道需要 7.79，还差约 640 米每秒。" | 速度 / 轨道根数 |

#### 滑行段专项脚本（★★ 全局最重要的讲解窗口）

演示模式在 E8（二级关机）后**自动暂停**，并弹出一个"讲解引导"浮层（可一键关闭）：

| 步骤 | 教师操作 | 学生看到 | 讲解要点 |
|---|---|---|---|
| 1 | 展开轨道根数面板 | 轨道俯视图：一条**不闭合**的椭圆，一端穿过地球 | "现在没有推力了，但它在继续上升——靠的是速度。" |
| 2 | 指向"近地点高度" | **负数**（实测 **−1617 km**，由积分器实时反算，非硬编码） | "近地点是负的。意思是这个椭圆的最低点在**地表以下**——它会掉回来。**它还没入轨。**" |
| 3 | 播放到 E10（实测远地点 T+571.4） | 三级点火，椭圆开始"胀大" | "我们要在远地点点火，把速度从 7.13 补到 7.79（还差约 650 米每秒），把近地点从负的 1617 公里抬到 200 公里以上。" |
| 4 | 播放到 E11 | 近地点数字从负爬到正，椭圆闭合成圆 | "这一刻，它才叫入轨。" |
| 5 | 关闭浮层，继续 | — | — |

> **这个脚本是整个项目科普价值最高的 3 分钟。** 如果只能保留一个功能，保留这个。

### 1.5 演示模式的保障措施

| 风险 | 保障 |
|---|---|
| 演示失败 | 全部失败判定禁用（F1–F5 关闭） |
| 弹道标定偏差导致未入轨 | 三级自动延长工作至达标（最多烧到 35 t）；仍不达标则记录日志但继续播放，结束时提示"演示数据偏差，请联系开发者" |
| 误触导致中断 | 玩家输入在演示模式完全禁用（节流、bias、点火全部锁定） |
| 讲解超时 | 滑行段暂停不限时 |
| 学生提问打断 | 任意时刻 `空格` 暂停，数据冻结可查 |

## 2. 挑战模式

### 2.1 引导方式：三阶段递进

| 阶段 | 触发条件 | 引导强度 | 具体表现 |
|---|---|---|---|
| **G1 手把手** | 玩家**前 2 次**飞行 | 强 | 底部"下一步"提示条全程常驻；每个决策点前 10 s 弹提示；操作键位高亮闪烁 |
| **G2 提示** | 第 3–5 次飞行 | 中 | 仅关键决策点（Max-Q、三级点火、三级关机）提示；其余隐藏 |
| **G3 无引导** | 第 6 次及以后 / 玩家手动关闭 | 无 | 仅告警（动压/过载/攻角超限预警） |

**引导可随时在设置中重置或关闭。** 硬核玩家第一次就能关掉。

### 2.2 "下一步"提示条的内容

| 时段 | 提示文案 |
|---|---|
| T−3 s | "按 **空格** 点火" |
| T+0–30 s | "起飞了。观察加速度表——它在持续上升，因为火箭在变轻。" |
| T+30–60 s | "已开始程序转弯。用 ↑ / ↓ 可以做小幅修正（±15°）。" |
| T+65 s | ⚠ "即将进入最大动压区。建议按 **Q** 降低推力到 80%。" |
| T+90–170 s | "Max-Q 已过。可以按 **E** 恢复满推力。" |
| T+175 s | "助推器燃料耗尽，即将分离。观察加速度的变化。" |
| T+230–448 s | "二级段。大气已很稀薄，主要看速度逼近 7.8 km/s。" |
| T+448–571 s | "滑行段。看近地点高度——它是**负数**（约 −1617 km），说明还没入轨。" |
| T+571 s（实测远地点） | "按 **空格** 点火三级。在远地点点火效率最高。" |
| T+571–804 s | **手动关机档（硬核 / 打开 `manualCutoff3` 的标准档）**："盯着轨道根数面板。近地点到 200 km、远地点不超过 240 km 时，按 **空格** 关机。"<br>**自动关机档（入门 / 标准）**："系统会在达标时自动关机。看近地点高度——它正从负值往上爬。" |

### 2.3 容错机制（核心：让硬核物理也能"打得成"）

| # | 机制 | 说明 | 为什么有效 |
|---|---|---|---|
| **T1** | **AP 托底 + bias 回中** | 玩家的 bias 输入会以 τ_bias 指数衰减回中（入门 6 s / 标准 10 s） | 单次失误会自愈，玩家专注"时机"而不是"手感" |
| **T2** | **超大推进剂储备** | 三级满载 59 t，标准任务只需 18 t。玩家飞得差可以烧到 59 t | 41 t 的储备 ≈ 2900 m/s 的额外 Δv，足以弥补几乎任何操作失误 |
| **T3** | **连续失败自适应** | 同类失败 2 次 → 该判据放宽 20% + 弹出知识卡；3 次 → 建议切入门档 | 保证不会卡死 |
| **T4** | **节点重开** | 失败后可回滚到最近节点，不清空知识卡与成就 | 降低重来成本 |
| **T5** | **不惩罚的"勉强入轨"** | h_p ≥ 100 km 即给分，只是评价低 | 学生第一次打就有正反馈 |
| **T6** | **无时间压力** | 除 Max-Q 窗口（约 20 s）外，所有决策都不限时 | 消除手速门槛 |

**T2 是本设计的关键**：真实运载火箭的推进剂余量只有 1%–3%，本模拟器因为"用登月火箭执行 LEO 任务"，天然拥有 **160% 的余量**。这不是妥协，是**真实物理带来的礼物**——而且它本身就是一个知识点（见 `vehicle.md` §5.2）。

### 2.4 评分（100 分）

| 项目 | 分值 | 计算方式 | 满分条件 |
|---|---|---|---|
| **入轨精度** | **40** | `40 × (1 − \|h_p−H\|/60 − \|h_a−H\|/60)`，下限 0<br>`H` = **当前目标轨道高度**（200 或 400 km） | 近/远地点都恰好等于目标高度 |
| **Δv 效率** | **30** | `30 × min(1, B / 实际消耗)`<br>`B` = **该目标轨道的三级推进剂预算**（200 km：**18 t**；400 km：**26 t**，见 `vehicle.md` §6.2） | 三级消耗 ≤ `B` |
| **Max-Q 控制** | **15** | `15 × clamp((40 − q_peak)/15, 0, 1)` | 动压峰值 ≤ 25 kPa |
| **过载控制** | **15** | `15 × clamp((6.0 − a_max)/1.5, 0, 1)` | 最大过载 ≤ 4.5 g |

**评级**：
| 总分 | 评级 | 文案 |
|---|---|---|
| ≥ 90 | **S · 任务专家** | "完美的飞行。中国航天需要你。" |
| 75–89 | **A · 优秀航天工程师** | "轨道精度与燃料效率都很好。" |
| 60–74 | **B · 合格飞行控制员** | "成功入轨，还有优化空间。" |
| 40–59 | **C · 见习学员** | "入轨了，但浪费了不少推进剂。" |
| < 40 | **D · 需要加练** | "成功就是成功。再试一次会更好。" |

**评分原则**：**"成功入轨"本身不计分也不扣分，分数量的是"飞得好不好"。** 这样第一次打的学生不会因为"分数低"而丧失成就感。

> **两个目标轨道共用同一张评分表，但基准随目标走**（`H` 与 `B` 都是变量，不是写死的 200 km / 18 t）。
> 最佳成绩按 `难度@目标高度` 分桶存档（`launchsim.best`），200 km 与 400 km 各记一份，不互相覆盖。
>
> ⚠ **跨目标可比性——已知风险，本轮不阻塞交付，但必须记账**：A2–A6 的门槛
> （精度 ≥ 36 分 / 三级 ≤ 16 t / 过载 ≤ 4.5 g / Max-Q ≤ 25 kPa / 重力损失 ≤ 1450 m/s）
> 是**按 200 km 目标标定**的绝对值。400 km 目标弹道更高（三级预算 26 t、滑行 309.5 s），
> 其中 **A3（三级 ≤ 16 t）与 A6（重力损失 ≤ 1450 m/s）在 400 km 下极可能不可达**
> ——这与刚修掉的 A8 是同一类问题（成就永远拿不到），只是更隐蔽。
>
> **处理口径（本轮即生效）**：
> 1. **不为迁就 400 km 去放宽 200 km 的门槛**——200 km 是默认档，它的门槛有实测数据支撑；
> 2. **A3 与 A6 的成就文案标注"以 200 km 目标为准"**，学生按 200 km 飞一定能拿到；
> 3. 若后续实测确认 400 km 下确实不可达，走"为 400 km 单设门槛"的方案（按目标分桶判定，
>    与 `C.TARGETS` 的既有结构一致），**不回头改 200 km 的数值**。

### 2.5 成就系统

> 成就按**理解程度**设计，不按通关次数（`concept.md` §3.1 胜任需求）。

| # | 成就名 | 条件 | 对应知识点 |
|---|---|---|---|
| A1 | **首次入轨** | 完成第一次成功入轨 | — |
| A2 | **精确入轨** | 入轨精度分 ≥ 36（近/远地点偏差 ≤ 12 km） | 轨道根数 |
| A3 | **高效飞行** | 三级消耗 ≤ 16 t（200 km 目标） | Δv 预算 |
| A4 | **平稳飞行** | 最大过载 ≤ 4.5 g | 节流时机 |
| A5 | **Max-Q 大师** | 动压峰值 ≤ 25 kPa | **K2** 动压 |
| A6 | **教科书式转弯** | 重力损失 ≤ 1450 m/s（200 km 目标） | **K3** 重力转弯 |
| A7 | **手动飞行** | 关闭自动驾驶（全手动）完成入轨 | 硬核操作 |
| A8 | **空间站轨道** | 在 400 km 目标轨道完成入轨 | 轨道高度 ↔ Δv 代价（三级预算 18 t → 26 t） |
| A9 | **数据核验员** | 在"核验"面板中停留累计 3 分钟 | 可核验性 |
| A10 | **教员** | 演示模式累计播放 10 次（教师成就） | — |

**成就展示**：解锁时右下角滑入小卡片（**不打断飞行**，不用模态弹窗）。飞行结束后在结算页集中展示。

> ### ⚖ 2026-09-03 变更：A8「满载荷」→「空间站轨道」
>
> **原定义**：A8「满载荷：用 70 t 载荷完成入轨」，判定条件 `ctx.payloadT === 70`。
> 70 t 载荷选项因弹道从未标定（实测近地点 h_p = −6368 km、整条轨道在地心以下；
> 动压峰值 575 kPa，为气动上限的 12.8 倍）已于同日从设置面板删除，载荷固定为 26 t。
> **该成就在删除那一刻起永远不可能解锁**——留着等于给学生一个永远拿不到的空勋章。
>
> **新定义**：A8「空间站轨道：在 400 km 目标轨道完成入轨」。
>
> **选择依据**：
> 1. **确实可达**：400 km 是用户决策 #8 指定的第二个目标轨道，与 200 km 一样
>    在入门 / 标准 / 硬核三档下全部标定通过（`constants.js` 的 `C.TARGETS[400]`）。
> 2. **补上了知识点空位**：原 A8 对应「运力边界」，改后对应「轨道高度 ↔ Δv 代价」
>    ——同一个火箭、同一段飞行，目标从 200 km 抬到 400 km，三级推进剂预算由 18 t
>    涨到 26 t（见 `vehicle.md` §6.2）。这是 K1（齐奥尔科夫斯基）最直观的一个
>    可对照实验，且是 A1–A7、A9、A10 都没覆盖的角度。
> 3. **不引入新状态**：判定只读 `ctx.sim.veh.targetAlt`，不跨局累计、不加存档键，
>    A9 / A10 与 `运行说明.txt` 的"成就有 10 个（A1–A10）"、UI 的十格徽章布局
>    全部不需要改。
>
> **命名说明**：不采用"深空之门"一类措辞。**400 km 仍然属于近地轨道，与"深空"相反。**
> 本项目对外承诺数据可核验，教师会照着成就卡念给学生听，成就名必须与物理事实一致。
> 「空间站轨道」直接对应设置面板里那个选项的原文（"400 km 空间站轨道"），
> 学生看到成就卡就知道去哪里再飞一次。
>
> **id 保持不变**：A8 不重编号，避免动到 `main.js` / `modes.js` 里的引用。

### 2.6 难度档位

| 参数 | **入门** | **标准** | **硬核** | **自定义** |
|---|---|---|---|---|
| AP 回中 τ_bias | 6 s | 10 s | ∞（不回中） | 可调 |
| bias 范围 | ±10° | ±15° | ±15° | 可调 |
| 三级点火 | 自动 | 手动 | 手动 | 可选 |
| 三级关机 | 自动 | **自动**（见下方裁决） | 手动 | 可选 |
| 手动节流 | 不可用 | 可用 | 可用 | 可选 |
| 全手动 pitch | 不可用 | 不可用 | **可用** | 可选 |
| 失败阈值缩放 | **×1.3**（放宽） | ×1.0 | **×0.85**（收紧） | 可调 |
| 引导强度 | G1 常驻 | G1→G2 自动降级 | 默认关闭 | 可选 |
| 载荷 | 26 t（深空版） | 26 t（深空版） | 26 t（深空版） | 26 t（**不可调**） |
| 目标轨道 | 200 / 400 km | 200 / 400 km | 200 / 400 km | 200 / 400 km |

**默认档：标准；默认目标轨道：200 km。**

> **载荷一行已于 2026-09-03 锁定。** 难度档**不再改变载荷**——载荷固定为梦舟 · 深空版 26 t，
> 由 `modes.js` 的 `Director.payloadT` 决定，与难度档、与目标轨道都无关。
> 原表写的"入门 14 t（近地版）/ 自定义 14 / 26 / 70 t"从未真正生效过：
> `set-difficulty` 只设 `director.difficulty`，选入门档实际跑的仍是 26 t，**文案在撒谎**。
> 14 t 与 70 t 选项现已从设置面板删除（两者弹道从未标定，见 `vehicle.md` §6.1）。
>
> **目标轨道一行同步更正。** 原表写"入门 / 标准 / 硬核 = 200 km，仅自定义可选 400 km"，
> 但设置面板的"目标轨道"下拉框与难度档是**两个独立控件**，三个难度档都能选 400 km。
> 两档目标各有一套独立标定的制导参数与入轨判据，见 `vehicle.md` §6.2。

> ### ⚖ 用户裁决优先于本条原始设计（三级关机）
>
> **裁决内容**：**标准档的三级关机改为"自动"；硬核档维持"手动"。**
> 本表原始设计为"标准档手动关机"，**该设计已被用户裁决覆盖，以本裁决为准。**
>
> **裁决理由**：标准档面向的是第一次上手的学生。手动关机的判读门槛是"同时盯近地点与远地点两个数、并在 ±20 km 窗口内按键"，一旦错过窗口，学生会**卡在最后一步反复失败**——而失败发生在"已经看见轨道了"的时刻，挫败感最强。改为自动关机后，标准档保留的是**两个真正有教学价值的决策点**（Max-Q 节流、三级点火时机），把纯操作精度的负担移交给系统。
>
> **实现落点**：`steering.js` 中 `DIFFICULTY.normal.autoCutoff3 = true`；同时提供设置项 `manualCutoff3` 作为回退开关（教师想让标准档学生也练手动关机时可打开）。
>
> **边界说明（本裁决只覆盖"关机"）**：标准档的**三级点火仍为手动**。理由：① 用户裁决在实现侧的落点是 `autoCutoff3`，只针对关机；② "在远地点点火"是 K4（入轨 = 横向速度够快）的核心决策，是标准档**唯一不可替代的知识点**，不应自动化。
> ⚠ **待主理人确认**：若用户原意是"标准档点火与关机都自动"，请回传，本行按裁决改写。

**入门档的额外保障**：三级点火/关机自动 → 学生只需处理 Max-Q 节流与 bias 修正两个决策点。

**硬核档的额外挑战**：bias 不回中意味着失误会累积；全手动 pitch 需要真正理解重力转弯；三级必须手动关机。

**标准档的决策点（修订后）**：Max-Q 节流 → 三级点火时机 → bias 修正。**共 3 个，关机由系统完成。**
