## 0. 全局约定

### 0.1 三套坐标系

| 坐标系 | 原点 | 轴向 | 单位 | 用途 |
|---|---|---|---|---|
| **箭体坐标（Body）** | 芯一级尾喷管出口平面中心 | +Y 沿箭轴指向头部，+X 向右 | 米 | 绘制火箭各部件、分离动画 |
| **世界坐标（World）** | 发射台中心地面点 | +Y 向上，+X 向右（东） | 米 | 场景布局、相机、地面/大气 |
| **屏幕坐标（Screen）** | 画布左上角 | +Y 向下 | 像素 | 最终渲染 |

**相机变换（唯一公式，全项目统一）：**

```js
screenX = (worldX - camX) * zoom + canvasW / 2
screenY = canvasH / 2 - (worldY - camY) * zoom
// zoom 单位：px / 米。起飞整箭可见时 zoom ≈ 1080 / 110 ≈ 9.8
```

### 0.2 缩放与 DPR

```js
canvas.width  = cssW * devicePixelRatio;   // 必须按 DPR 放大位图，否则大屏/高分屏糊
canvas.height = cssH * devicePixelRatio;
ctx.setTransform(devicePixelRatio, 0, 0, devicePixelRatio, 0, 0);
// 所有 Canvas 绘制使用 CSS 像素坐标，由 setTransform 统一处理
```

### 0.3 通用命名

`CZ10_` 前缀 = 长征十号部件；`MZ_` 前缀 = 梦舟飞船；`FX_` 前缀 = 特效；`HUD_` 前缀 = 仪表；`UI_` 前缀 = 界面元件。

**`cutaway` 半透明剖视规格（演示模式）**

| 项 | 规格 | 理由 |
|---|---|---|
| 罩体填充透明度 | **0.25** | ✅ 已确认合适。0.25 既能透出内部飞船，又保留罩体存在感；再低（<0.15）罩体会"消失"，学生理解不了"它在里面" |
| **切口描边（需补）** | `stroke: var(--c-primary)`，`stroke-width: 3`，**`stroke-dasharray: none`（实线）** | 工程制图剖视惯例：剖切面必须有明确粗轮廓。用**主色**而非强调色——`art-bible` §8 锚点 3 规定橙 = 能量，不应被剖切功能稀释 |
| **缝线 `.rk-seam` 保持虚线** | `--c-accent` 3 px，`stroke-dasharray: 8 6` | ✅ 已正确。符合全局规则「虚线 = 参考/预测/目标，实线 = 实际/当前」——分离面是"将来会分开的地方"（虚线），剖切切口是"当前状态"（实线） |
| **内部飞船描边加粗（建议补）** | `.is-cutaway .rk-ship-body{ stroke-width: 3 }`（2 → 3，**色不变仍用 `--c-primary`**） | 让"露出来了"更醒目。用线宽而非颜色强调，同样是为了不稀释"橙=能量"锚点 |
| 切换动效 | `fill-opacity` 240 ms 过渡，`cubic-bezier(0.4,0,0.2,1)` | 与全局状态切换时长一致 |

```css
/* 剖切态：罩体半透明 + 切口实线加粗 + 内部飞船描边加粗 */
.is-cutaway .rk-fair-body{
  fill-opacity:.25;
  stroke:var(--c-primary);      /* 用主色，不用强调色 */
  stroke-width:3;               /* 常态 2 → 剖切 3 */
  stroke-dasharray:none;        /* 实线：剖切是当前状态 */
  transition:fill-opacity .24s cubic-bezier(.4,0,.2,1);
}
.is-cutaway .rk-ship-body{ stroke-width:3; }   /* 色不变，只加粗 */
```

> **实现提示**：梦舟飞船（`rk-ship`）**常驻绘制**的做法是正确的——它的可见性由罩体的 `fill-opacity` 自然控制，不需要额外的显示/隐藏逻辑，也避免了剖切切换时的闪烁。

### 1.4 发动机喷管排布（一级/助推器通用）

每个 5.0 m 直径模块底部，**7 台 YF-100K，中心 1 + 外圈 6**：

| 参数 | 值 |
|---|---|
| 外圈分布圆半径 R | **1.65 m** |
| 外圈 6 台角度 | 0°, 60°, 120°, 180°, 240°, 300° |
| 相邻外圈喷管中心距 | 1.65 m |
| 喷管出口直径 | **1.40 m** |
| 喷管可见长度（伸出箭体底部） | **2.40 m** |
| 最外缘到箭体壁余量 | 2.35 m < 2.50 m ✅ |

```js
// 伪代码：生成 7 台喷管中心（模块本地坐标，单位 m）
const NOZZLES = [[0, 0]];
for (let i = 0; i < 6; i++) {
  const a = (i * 60) * Math.PI / 180;
  NOZZLES.push([Math.cos(a) * 1.65, Math.sin(a) * 1.65]); // x 为横向，y 为屏幕纵深（侧视图仅用 x）
}
// 侧视图：只按 x 排序绘制，y 用于决定绘制顺序（y>0 画在前）与亮度微调
```

**视觉校验点**：7 台喷管在 5 m 圆内是**紧密但不重叠**的。若画出来有间隙过大或重叠，说明 R 或喷管直径错了。

### 3.1 FX_PLUME · 发动机尾焰

**绘制方式：Canvas（必须）** —— 需要逐像素渐变、`globalCompositeOperation = 'lighter'` 合成、逐帧扰动。

#### 三层叠加结构

| 层 | 内容 | 渐变 | alpha |
|---|---|---|---|
| L1 内核 | 白热核心，长度 0.35 L | 径向 `#FFFBF0` → `#FFB54A` | 1.0 |
| L2 主焰 | 主焰锥，长度 1.0 L | 线性（沿 +Y 向下）`#FFD27A` → `#FF6A13` → 透明 | 0.85 |
| L3 外焰/烟羽 | 扩散羽流，长度 1.4 L，宽度 2.2 W | 线性 `#FF6A13` @ 0.25 → 透明 | 0.25 |
| 合成 | **深色主题 `'lighter'`**；**浅色主题 `'source-over'` + 浅色专用 4 层规格**（见下方「浅色主题专用尾焰」） | | |

> ⚠️ **`lighter` 不能用于浅色主题**：`lighter` 是把像素值相加，在深色底上形成"越叠越亮"的辉光；但在浅色底（`#eef3f8`，相对亮度 0.89）上，任何叠加都会迅速推到 255，**整片过曝成白色**，尾焰反而消失。这是投影演示的主场景，必须避免。

```js
// 伪代码：单模块尾焰（模块本地 → 屏幕坐标）
function drawPlume(ctx, x, yBottom, width, L, throttle, t, reducedMotion) {
  const W = width * (0.9 + 0.4 * throttle);              // 节流↑ 焰更宽
  const amp = reducedMotion ? 0 : 0.06 * L;
  const path = new Path2D();
  const STEPS = 12;
  for (let i = 0; i <= STEPS; i++) {
    const s = i / STEPS;                                  // 0 = 喷口, 1 = 焰尾
    const yy = yBottom + s * L;
    const wob = Math.sin(t * 7.0 + s * 1.5) * amp * s;    // ω=7 rad/s
    const halfW = (W / 2) * (0.35 + 0.65 * Math.sin(Math.PI * Math.pow(s, 0.7)));
    path.lineTo(x + wob + halfW, yy);
  }
  for (let i = STEPS; i >= 0; i--) { /* 镜像回描左半边 */ }
  path.closePath();
  // 依次用 L3/L2/L1 的渐变 fill（长度分别取 1.4L / 1.0L / 0.35L）
}
```

#### 浅色主题专用尾焰：暗芯 + 亮边（4 层，`source-over`）

**为什么不能用深色那套颜色**：深色主题靠"焰芯最亮（近白）"制造发光感，因为底是暗的。浅色主题底是亮的（`#eef3f8`），近白焰芯 `#FFF8E1` 对背景的对比度只有约 **1.0:1** —— **完全看不见**。

**解决思路反转**：浅底上要"看得见"，靠的是**明度低于背景**，不是高于背景。所以把焰芯从"最亮"改成"最深"，并补一圈描边定边界。这也是蓝图风格（细描边 > 渐变填充）本来的语言。

| 层（绘制顺序自上而下） | 长度 | 宽度 | 颜色 / 渐变 | alpha | 作用 |
|---|---|---|---|---|---|
| **L3 外焰**（先画，最外） | 1.40 L | 1.00 W | 线性 `#FF7A1A` → 透明 | 0.22 | 弥散外围 |
| **L2 主焰** | 1.00 L | 0.72 W | 线性 `#FFC24A` → 透明 | 0.55 | 焰体主体 |
| **L1 焰芯**（暗芯） | 0.35 L | 0.42 W | 径向 **`#C2410C`** → `#C2410C` 透明 | **0.90** | **在浅底上提供明度对比** |
| **L0 描边**（最后画） | 沿 L2 主焰轮廓 | — | `#C2410C` 实线，2 px | 1.00 | 定边界，蓝图硬轮廓 |

```js
// 浅色主题专用（th.composite === 'source-over' 时走这条分支）
var DARK_CORE = '194,65,12';               // #C2410C —— 暗芯与描边同色

// L3 外焰
var g3 = ctx.createLinearGradient(0, 0, lenPx * 1.4, 0);
g3.addColorStop(0, gm.vac ? 'rgba(' + th.plumeVac + ',0.20)' : 'rgba(255,122,26,0.22)');
g3.addColorStop(1, 'rgba(255,122,26,0)');
flame(1.4, 1.0, g3);

// L2 主焰
var g2 = ctx.createLinearGradient(0, 0, lenPx, 0);
g2.addColorStop(0, gm.vac ? 'rgba(' + th.plumeVac + ',0.40)' : 'rgba(255,194,74,0.55)');
g2.addColorStop(1, 'rgba(255,194,74,0)');
flame(1.0, 0.72, g2);

// L1 暗芯（关键：不是近白，是深赭橙）
var g1 = ctx.createRadialGradient(lenPx * 0.06, 0, 0, lenPx * 0.06, 0, lenPx * 0.35 + halfPx);
g1.addColorStop(0, gm.vac ? 'rgba(30,60,100,0.55)' : 'rgba(' + DARK_CORE + ',0.90)');
g1.addColorStop(1, 'rgba(' + DARK_CORE + ',0)');
flame(0.35, 0.42, g1);

// L0 描边：沿 L2 轮廓 2 px 实线（需 flame() 支持 fill 后同路径 stroke）
ctx.strokeStyle = gm.vac ? 'rgba(27,108,168,0.75)' : 'rgb(' + DARK_CORE + ')';
ctx.lineWidth = 2;
ctx.stroke(l2Path);                        // 复用 L2 的 Path2D，不重建
```

**关键参数说明：**

| 参数 | 值 | 理由 |
|---|---|---|
| 暗芯色 | `#C2410C` | 对 `#eef3f8` 对比度 **4.63:1**，清晰可见；与 `--c-accent-text` 同色，保持"橙 = 能量"语义统一 |
| 焰芯明度 | **低于** 外焰明度 | 浅底上的可见性来自"比背景暗"，这是与深色主题**完全相反**的明度方向 |
| 真空羽流暗芯 | `#1E3C64`（深蓝）@ 0.55 | 真空羽流是蓝色调，不能用橙色暗芯；用深蓝保持色相正确 |
| 真空羽流描边 | `#1B6CA8`（`--c-primary-2`）@ 0.75，2 px | 同上 |
| 描边线宽 | 2 px | 与全局"结构线最小 2 px"一致；**不随缩放变细** |
| 扰动 | `amp = reducedMotion ? 0 : 0.06 * lenPx` | 与深色主题相同，两主题行为一致 |

> **降级说明**：这条路径的尾焰观感会比深色主题"实"一些、没有辉光通透感。**这是为投影可读性做的取舍，接受。** 演示模式（投影）本来就不该追求发光特效——投影仪的动态范围有限，辉光在幕布上会糊成一团亮斑。

| 状态 | 高度 | 节流 | 焰长 L | 焰宽 W | 主色 | 特征 |
|---|---|---|---|---|---|---|

**21 台焰流的汇聚规则（易错点）**：

| 高度 | 绘制形态 |
|---|---|
| 0–3 s（起飞瞬间） | **3 股独立焰流**（芯 1 股 + 2 助推各 1 股），每股宽 = 5.0 m |
| 3–8 s | 3 股边缘开始融合，`lighter` 合成区亮度叠加 |
| >8 s | **合并为 1 股**，宽度 = 16.2 m（箭体总宽） |

用 `mergeFactor = clamp((t - 3) / 5, 0, 1)` 在两形态间插值（每股的 X 中心向箭体轴心内收）。

#### 地球弧段采样密度（✅ 确认折线画法，补充采样要求）

**折线近似圆弧是标准且正确的工程做法**，视觉上完全可接受——只要采样够密，肉眼分辨不出折线与圆弧。采样不足才会出现"多边形感"（能看到直线段）。

| 项 | 规格 |
|---|---|
| 采样点数 | `N = clamp(ceil(屏幕弧长px / 4), 8, 2000)`，即**每 4 屏幕像素一个采样点** |
| 精度指标 | **弦高误差 ≤ 0.5 px**（折线段到真实弧的最大偏差）。每 4 px 采一点在 R 极大时误差远小于此，足够 |
| 低缩放（地面附近，R 极大、弧近乎直线） | N 取下限 8–32 即可，无需高精度 |
| 高缩放（轨道视图，地球是大圆且可见完整轮廓） | 按公式自动增密；**若屏幕半径 R_screen < 20000 px，改用 `ctx.arc()` 直接画圆**（此时无需折线近似，更快更精确） |
| 线宽 | 3 px，**不随缩放变细**（`asset-spec` §5.2：所有结构线 ≥2 px） |
| 端点处理 | 弧段两端各多采 1 个点并延伸到视口外，避免"弧线在半空中截断" |
| 平滑 | `ctx.lineJoin = 'round'`，避免折点处出现尖角 |

```js
// 伪代码：可见弧段采样
function drawEarthArc(ctx, cam, altitude, R_earth) {
  var h = Math.max(0, altitude);
  var halfAngle = Math.acos(R_earth / (R_earth + h));   // 可见地平线对应的地心半角
  var spanPx = /* 弧段在屏幕上跨越的像素长度，由 cam.zoom 换算 */;
  var N = Math.min(2000, Math.max(8, Math.ceil(spanPx / 4)));
  var R_screen = R_earth * cam.zoom;

  if (R_screen < 20000) {                                // 半径可控 → 直接画圆弧
    ctx.arc(cx, cy, R_screen, a0, a1);
  } else {                                               // 半径过大 → 折线近似
    ctx.beginPath();
    for (var i = 0; i <= N; i++) {
      var a = -halfAngle + (2 * halfAngle) * (i / N);
      var p = cam.toScreen(R_earth * Math.sin(a), R_earth * Math.cos(a), W, H);
      if (i === 0) { ctx.moveTo(p.x, p.y); } else { ctx.lineTo(p.x, p.y); }
    }
    ctx.stroke();
  }
}
```

### 4.2 ORB_ELEMENTS · 轨道根数可视化

3. 两平面交线（交点线）画为 `i` 角度的斜线
4. 在升交点处画**角度弧** + 文字 `i = 19.6°`，弧用 `--c-accent` 2 px
5. 可旋转视角（挑战模式），演示模式下固定为 30° 俯视角

| 文字 | 当前阶段名常驻显示（20 px / 600），如「二级飞行」 |
| 关系 | 与 `HUD_TIMELINE` 是同一数据的粗/细两种视图：**节点数 ≤5，避免认知过载** |

## 7. SVG vs Canvas 选型总表

### 7.1 选型原则（一句话）

> **静态结构走 SVG（可缩放 / 可访问 / 可主题），动态像素走 Canvas（高性能 / 可合成）。**

### 7.2 决策依据

| 维度 | SVG 优 | Canvas 优 |
|---|---|---|
| 缩放 | 矢量，**任意缩放锐利**（4K/8K 大屏、教师放大讲解不失真） | 位图，需按 DPR 重设尺寸，放大后糊 |
| 主题切换 | **CSS 变量直接生效**，零成本 | 需手动重绘，颜色必须读主题常量 |
| 可访问性 | **DOM 可被屏幕阅读器/键盘访问**，支持 ARIA | 完全不可访问，需额外 DOM 镜像 |
| 维护 | 声明式，结构可读 | 命令式，逻辑密集 |
| 图元数量 | **>300 节点每帧更新会掉帧** | 数千图元仍流畅 |
| 像素合成 | 不支持 `lighter` 辉光等合成 | **支持完整合成与逐像素渐变** |
| 渐变/噪声 | 表现力弱 | 表现力强 |
| 动画 | `transform` GPU 加速，适合位移/旋转 | 需手动逐帧重绘 |

### 7.3 分配表

| 元素 | 选型 | 核心理由 |
|---|---|---|
| 火箭各级轮廓、分离动画 | **SVG** | 教师会放大讲解某一级，矢量必须锐利；分离动画用 `transform` 即可，GPU 加速 |
| 梦舟飞船（含太阳翼） | **SVG** | 同上；太阳翼展开用 transform 逐段伸展 |
| 发射塔架 | **SVG** | 静态结构；需被放大讲解 |
| UI 图标（全部） | **SVG** | `<symbol>` 集中 + `<use>` 引用，`currentColor` 自动跟随主题 |
| HUD 框架、量条槽、刻度、面板边框 | **SVG / DOM+CSS** | 静态 + 可访问 |
| HUD 数值文字 | **DOM** | 可访问性 + `tabular-nums`；更新用 `textContent`，几十个节点性能无压力 |
| 轨道线、根数标注、近远地点标记 | **SVG** | 矢量、低频更新、需标注与文字标签 |
| Δv 预算条 | **DOM + CSS** | 最简单且天然可访问 |
| 讲解浮层 | **DOM + SVG 图标** | 需要文字排版与 ARIA |
| 事件时间线 | **DOM + SVG** | 需文字标签、键盘可交互 |
| 成就徽章 | **SVG** | 矢量、三态主题切换 |
| 星空背景 | **Canvas** | 600 图元；需离屏缓存 + 单次 drawImage |
| 地球与大气渐变 | **Canvas** | 逐帧连续径向渐变，随高度平滑变化 |
| 尾焰 / 烟羽 / 羽流 | **Canvas** | 三层渐变 + `lighter` 合成 + 逐帧扰动，SVG 无法实现 |
| 分离碎片 / 烟环 | **Canvas** | 粒子，短生命周期 |
| 轨迹拖尾 | **Canvas** | 点数累积到 2000+，SVG 会掉帧 |
| Q / G 实时曲线 | **Canvas** | 每帧追加点，最多 3000 点 |
| 地面 / 海面细节 | **Canvas** | 随高度淡出，需连续 alpha |

### 7.4 图层栈（z-index，自下而上）

| 层 | 内容 | 技术 | 说明 |
|---|---|---|---|
| **L0** | 星空 + 地球 + 大气 + 地面 | Canvas | 视差层，位移差 ≤1.5× |
| **L1** | 轨迹拖尾 | Canvas | 世界坐标存储，每帧按相机变换重绘 |
| **L2** | 尾焰 + 烟羽 + 碎片 + 烟环 | Canvas | **必须在箭体之下**，否则焰会遮住箭体轮廓（破坏"工程蓝图"的清晰性） |
| **L3** | 火箭箭体 + 塔架 + 飞船 | **SVG** | 结构与教学主体 |
| **L4** | HUD + 讲解浮层 + 时间线 + 控件 | DOM + SVG | 全部可访问 |

**关键约束**：L2（尾焰）在 L3（箭体）**之下**。这是本项目的重要视觉决策：工程蓝图风格要求箭体轮廓永远清晰，尾焰不得覆盖箭体。深色主题下若想表现"焰光包裹箭体"，只允许在箭体外轮廓外扩 6 px 处画一圈 `--c-accent` @ 20% 的柔光，**不得覆盖箭体内部**。
