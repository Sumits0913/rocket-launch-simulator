## ⚠️ 维护警告：调色板有两份，改色必须同时改两处

**Canvas 读不到 CSS 变量，这是浏览器限制，无法绕过。** 因此本项目的调色板**必然存在两份独立维护的色值**，任何只改一处的操作都会导致画面撕裂（典型症状：箭体是新蓝、尾焰是旧蓝）。

| # | 位置 | 文件 | 标识 | 覆盖范围 |
|---|---|---|---|---|
| **①** | **CSS 变量（DOM / SVG / HUD 层）** | `index.html` | `:root{...}` 与 `html[data-theme="dark"]{...}` 两个块，变量前缀 `--c-` / `--sev-` | 面板、文字、SVG 箭体描边与填充、HUD、控件 |
| **②** | **Canvas 主题常量（背景 / 特效层）** | `src/app/render.js` | `var THEME = { dark: {...}, light: {...} }` | 天空渐变、地面、大气、尾焰、烟羽、轨迹拖尾、星空 |

**执行规则：**

1. **改任何一个颜色，必须同时改这两处。** 两处色值必须逐位相同（大小写不敏感，`#ff6a13` = `#FF6A13`）。
2. **两处共用同一套语义键名映射**（见下表），改色时按语义定位，不要按位置猜。
3. 若某颜色只存在于其中一处（如尾焰色只在 Canvas、面板色只在 CSS），**在另一处留一行注释说明"此色仅存在于另一侧"**，避免后来者误以为漏了。

**语义 → 两处键名映射表**

| 语义 | ① `index.html` CSS 变量 | ② `render.js` THEME 键 |
|---|---|---|
| 画布底 / 天空底部渐变 | `--c-bg` | `sky1`（顶部渐变对应 `sky0`，CSS 侧无对应） |
| 主体结构色（蓝） | `--c-primary` | `trail`（轨迹拖尾用主色系） |
| 能量强调色（橙） | `--c-accent`（文字版 `--c-accent-text`） | `plumeOut`（外焰）/ `plumeMid`（中焰）/ `plumeCore`（焰芯） |
| 真空羽流 | （CSS 侧无） | `plumeVac` |
| 地面 / 地表 | （CSS 侧无，塔架用 `--c-text-2`） | `ground` / `groundLine` |
| 大气渐变 | （CSS 侧无） | `atmo` |
| 合成模式 | （CSS 侧无） | `composite` |

> **允许的差异**：尾焰的 `plumeCore/Mid/Out` 是**发光特效的色阶**，允许与 UI 的 `--c-accent` 有明度差（焰芯更亮、外焰更饱和）；但**色相必须一致**（同属橙色系 H ≈ 25°±8°），否则 `art-bible` §8 锚点 3「橙 = 能量」的条件反射建立不起来。

## 1. 视觉定位（一句话）

**一本会动的航天工程蓝图——用测控仪表的语言，把真实物理讲成一堂看得懂的课。**

拆解三个关键词：

| 关键词 | 含义 | 反面（我们不要） |
|---|---|---|
| 工程蓝图 | 网格、细描边、标注线、比例感，画面是"图纸"不是"插画" | 写实渲染、材质贴图、阴影体积感 |
| 测控仪表 | 等宽数字、条形量、语义色、事件时间线，画面能承载专业数据 | 拟物仪表盘、旋钮、指针、拟真按钮 |
| 看得懂 | 每个视觉编码都可被解释、可被教师口述讲解 | 只为好看的装饰、说不清含义的特效 |

## 2. 参考方向（气质来源与教学适配性）

本项目**不做深色深空风**（那是另一套独立项目的方向），主身份是**浅色工程蓝图**。

| 参考方向 | 借鉴什么 | 为什么适合科技馆大屏教学 |
|---|---|---|
| **工程蓝图 / CAD 图纸** | 网格底、细描边、尺寸标注线、分层线框 | 天然"教学语境"：学生看到的不是游戏画面，是一张正在计算的图纸，教师可直接指着讲"这一级在这里分离" |
| **航天测发大厅测控台** | 分区面板、等宽数字、语义色状态灯、事件时间线 | 还原真实任务语境，让学生理解"工程师看到的就是这些数据"，形成职业认知 |
| **任务控制台（Mission Console）** | 左视图 + 右数据的固定构图、低饱和底 + 高饱和强调 | 视线路径稳定，教师讲解时学生知道"该看哪儿"，不用每次重新找焦点 |
| **教科书信息图** | 剖面示意、阶段分解、箭头标注 | 支持"分步讲解"，演示模式可逐帧拆解一个物理过程 |

**为什么不做深色深空风**：教室投影几乎不可能全黑（环境照度 100–300 lux），投影黑位被环境光抬高后，深色主题上的亮字对比度会从标称 8:1 崩到约 3.4:1（详见 `accessibility.md` 第 3 节的量化推导）。**浅底深字是投影场景的工程正确解，不是审美偏好。**

## 3. 色彩系统

### 3.1 主题策略

| 主题 | 用途 | 默认 | 理由 |
|---|---|---|---|
| **蓝图浅色（Blueprint Light）** | 演示模式（教室投影 / 大屏讲解） | ✅ **默认主题** | 投影环境下对比度稳定，远距可读性最优 |
| **测控深色（Console Dark）** | 挑战模式（学生本机直视、显示器/平板） | 挑战模式默认 | 自发光显示器下深色沉浸感强，接近真实测控台 |
| **高对比（High Contrast）** | 可访问性选项（可访问性面板手动开启） | 关闭 | 覆盖全部主题变量，给低视力/强环境光场景兜底 |

**实现硬规则**：所有颜色必须定义为 CSS 自定义属性（DOM/UI 层）与 JS 主题常量对象（Canvas 层）的**同一份数据源**，通过 `data-theme` 属性切换。**禁止在代码中出现裸 hex 值。** 两套主题必须共用同一套语义键名（`--c-bg`、`--c-surface`、`--c-text-1`…），不得按主题改名。

#### 语义色（状态编码）

四档语义色沿 **青绿 → 琥珀 → 橙 → 红** 的单向梯度排列，色相与明度同时递进，**在红绿色盲下仅靠明度顺序也能读出严重程度**。

| 语义 | 图形色（填充/描边/状态点） | 文字色（用于文本与细线） | 文字色对比度 | **形状编码（强制）** | 图标尺寸 | 典型触发 |
|---|---|---|---|---|---|---|
| 标称 / 成功 Nominal | `#0D9488` | `#0B524B` | **8.09:1** ✅ | **实心圆**（0 角）+ 对勾 | 24 px | 参数在安全包线内、入轨成功、成就解锁 |
| 注意 Caution | `#F59E0B` | `#6B4500` | **7.59:1** ✅ | **三角形**（3 边）+ 感叹号 | 28 px | 接近限值（如 Q 达峰值 80%） |
| 告警 Warning | `#EA580C` | `#9A3412` | **6.57:1** ✅ | **菱形**（4 边）+ 感叹号 | 32 px | 超出标称、姿态偏差大、推进剂低 |
| 危险 Critical | `#DC2626` | `#8E1414` | **8.37:1** ✅ | **八角形**（8 边）+ 叉 | 36 px | 超出结构/过载极限、任务失败 |
| 未激活 / 中性 | `#B8C4D0` | `#7C8896` | 3.24:1 | 空心圆（1 px 描边） | 24 px | 未开始阶段、数据无效、未解锁 |

> **关键设计决策 1 — 标称色用青绿不用纯绿**：纯绿 `#16A34A` 在红绿色盲（deuteranopia/protanopia）下与红色 `#DC2626` 明度接近、难以区分；青绿 `#0D9488` 被感知为偏蓝，与红橙在蓝-黄轴上分离，色觉障碍者可稳定分辨。

> **关键设计决策 2 — 严重度用"形状边数"编码，颜色只是辅助**：上表四档语义色去饱和后的相对亮度为 0.090 / 0.439 / 0.246 / 0.168，**并非单调递增**（红橙系在明度上天然接近，无法通过选色绕过）。因此本项目规定：**形状边数递增 = 严重度递增，图标尺寸递增 = 严重度递增**，这是与色觉、与明度完全无关的双重形体编码。
>
> 在科技馆大屏 / 教室投影场景下，颜色会因投影色偏、环境光、屏幕老化而失真，**形状轮廓不会**；远距观看时学生先辨识的也是形状。所以本项目**以形状为主编码、颜色为辅助编码**——这与常见的"颜色为主"做法相反，是本场景的刻意选择。完整推导见 `accessibility.md` 第 2 节。

| `--c-primary` | `#003A8C` | `#66B2FF` |
| `--c-accent` | `#B34700` | `#FFA860` |
| 标称 / 成功 | `#005F55` | `#5FF0DF` |
| 注意 | `#6B4500` | `#FFD54A` |
| 告警 | `#9A3412` | `#FFA45C` |
| 危险 | `#8E1414` | `#FF9A9A` |

### 3.5 投影环境对比度校验（硬指标）

**设计目标不是 WCAG AA 的 4.5:1，而是 7:1（AAA 级）。** 理由如下：

教室投影（非全黑，环境照度 100–300 lux）下，投影画面黑位被环境光抬高，实测有效对比度仅为标称值的 **30–50%**。以深色主题的次级文字为例：

| 场景 | 前景 | 有效背景 | 对比度 | 判定 |
|---|---|---|---|---|
| 标称（全黑放映室） | `#94A6B8` | `#0B1220` | 7.52:1 | ✅ 达标 |
| 教室投影（黑位抬至 ≈ `#3A3A3A`） | `#94A6B8` | `#3A3A3A` | **3.40:1** | ❌ 不达标 |
| 浅色主题 + 教室投影（白位基本不变，读数仍高） | `#46566A` | `#F4F6F8` | 6.74:1 → 约 5.5:1 | ✅ 仍可读 |

**由此得出三条执行规则：**

1. **所有正文与数据文字，标称对比度 ≥ 7:1**；仅 ≥36 px 粗体标题可放宽至 4.5:1。
2. **演示模式（投影）强制浅色主题**，不允许用户在演示模式下切到深色（设置项置灰并给出原因提示）。
3. **任何 ≤3:1 的颜色组合，只允许用于装饰**（网格、分隔线、禁用态），不得承载任何需要被读懂的信息。

## 4. 字体方案

### 4.1 约束

**零外部字体文件**（用户双击本地 HTML 打开，不能联网、不能有 woff/ttf 依赖）。全部使用操作系统自带字体栈。

### 4.2 字体栈

```css
/* ① 中文 UI 栈：正文、标题、按钮、标签 */
--font-ui: "Microsoft YaHei UI", "Microsoft YaHei", "PingFang SC",
           "Hiragino Sans GB", "Source Han Sans SC", "Noto Sans CJK SC",
           "WenQuanYi Micro Hei", sans-serif;

/* ② 等宽数字栈：HUD 全部数值、时间、坐标、版本号（必须） */
--font-mono: "Cascadia Mono", "Consolas", "DejaVu Sans Mono", "Menlo",
             "Courier New", monospace;

/* ③ 可选装饰数字栈（大号标题数字，缺失时静默回退到 ②，不得因此破版） */
--font-display: "Bahnschrift", "DIN Alternate", var(--font-mono);
```

**规则：**

- **HUD、时间线、坐标、任何会逐帧变化的数值，一律用 `--font-mono`**（等宽防止数字跳动导致整个 HUD 抖动）。
- `--font-display` 仅用于静态大标题（如"入轨成功"），且必须设计回退容错：不同字宽下不得破版。
- 中文与数字混排时，先写中文栈再写等宽栈，让中文命中中文字体、数字命中系统等宽（浏览器会按字符逐个 fallback）。
- **数字永远开启 `font-variant-numeric: tabular-nums;`**（即便字体本身等宽，这是双保险）。

### 4.3 字号阶梯（基准：1920×1080）

**最小字号硬下限：**

- **拉丁字母与数字：18 px**（mono 字体，笔画简单；仅限静态内容——单位、角标、时间戳、图例）
- **中文：20 px**（中文笔画密度高于拉丁字母，需 ×1.2 修正；推导见 `accessibility.md` 3.2）
- **任何情况下不允许出现 <18 px 的文字。**

| 层级 | 字号 | 字重 | 字体 | 行高 | 用途 |
|---|---|---|---|---|---|
| `--fs-micro` | **18 px** | 400 | mono | 1.4 | 单位、角标、时间戳、图例（**绝对下限**） |
| `--fs-caption` | 20 px | 400 | ui | 1.5 | HUD 组标签、次级说明 |
| `--fs-body` | 22 px | 400 | ui | **1.7** | 讲解浮层正文、提示文本 |
| `--fs-body-lg` | 28 px | 400 | ui | **1.7** | 演示模式大字号增补（一键切换） |
| `--fs-hud` | 28 px | 600 | mono | 1.2 | HUD 常规数值 |
| `--fs-hud-lg` | 40 px | 700 | mono | 1.1 | HUD 焦点数值（速度/高度） |
| `--fs-title-sm` | 24 px | 600 | ui | 1.4 | 区块标题、面板标题 |
| `--fs-title` | 36 px | 700 | ui | 1.3 | 讲解浮层标题、阶段名 |
| `--fs-title-lg` | 48 px | 700 | ui/display | 1.2 | 演示模式大字号增补标题 |
| `--fs-display` | 64 px | 700 | mono/display | 1.0 | 主视图大数字（速度/高度主显示） |
| `--fs-display-xl` | 96 px | 700 | mono/display | 1.0 | 里程碑数字（入轨速度、Δv 结算） |

**响应式缩放（无构建，纯 CSS）：**

```css
/* 基准 1080p，随视口高度线性缩放，但设死上下限 */
--ui-scale: clamp(0.75, calc(100vh / 1080), 2.0);
font-size: calc(22px * var(--ui-scale));
```

- **缩放后仍需满足：任何文字的渲染结果 ≥ 18 px。** 在 1080p 及以下视口，`--ui-scale` 下限锁死为 1.0（宁可滚动，不可缩小到不可读）。
- 用户可在设置中叠加 **100% / 125% / 150%** 三档 UI 缩放，与自动缩放相乘。

### 4.4 字重与可读性规则

| 规则 | 说明 |
|---|---|
| **禁止 200/300 细字重** | 中文笔画在投影下端易糊，细字重远看会消失 |
| 正文 400，数值 600，标题与警示 700 | 数值加粗是为了在投影泛白时保住笔画 |
| 中文最小有效字重 = 400 | — |
| **中文字号比同场景拉丁文大 1–2 px** | 中文无升部降部、笔画密度高，视觉更小 |
| 中文正文行高 **1.7**（英文常用 1.5） | 中文视觉密度更高，需更大行距 |
| 数字仪表行高 1.0–1.2 | 仪表是紧凑排版，不需要阅读行距 |

## 5. 形状语言与线条规范

### 5.1 形状语言

| 元素 | 圆角 | 说明 |
|---|---|---|
| 面板 / 卡片 | **6 px** | 工程感但不过分硬，避免割裂感 |
| 按钮 | **4 px** | 比面板小，显得"可操作" |
| 输入框 / 滑块槽 | 4 px | — |
| 状态点 / 徽标底 | 全圆（50%） | 状态点是唯一的圆形元素，形成识别 |
| 进度条 / 量条 | **2 px** | 高 10 px，圆角 2 px |
| 火箭箭体 | **0（硬边）** | 圆柱与锥体，禁用圆润卡通造型 |
| 成就徽章 | 六边形（尖角） | 工程感，区别于常见圆形游戏徽章 |
| 弹窗 / 讲解浮层 | 8 px | 最上层元素，圆角略大以示层级 |

**核心原则：形状服从功能。** 可交互 → 略圆；结构/工程 → 硬边；状态 → 圆形；成就 → 六边形。**禁止为好看而加圆角或倒角。**

### 5.2 线条与描边

| 用途 | 线宽（1080p） | 颜色（浅色主题） | 说明 |
|---|---|---|---|
| 蓝图网格 | 1 px | `#E3E9EF` | 32 px 主网格 + 8 px 次网格（次网格更淡，可省略） |
| 装饰分隔线 / 图表刻度 | 1 px | `#D3DAE2` | — |
| 结构细节线（箭体分段、塔架桁架） | **2 px** | `#0B3D6B` | **2 px 是投影下的最小可见线宽** |
| 主轮廓（火箭外形、面板边框） | **2 px** | `#0B3D6B` / `#7C8896` | — |
| 强调轮廓（选中、当前阶段、飞船） | **3 px** | `#FF6A13` | — |
| 标注引线（讲解浮层指向箭头） | 2 px + 箭头 | `#FF6A13` | 端点为实心三角箭头 |
| 轨道线（当前轨道） | 2 px | `#1B6CA8` | 实线 |
| 轨道线（目标/参考轨道） | 2 px | `#7C8896` | 虚线 `6 4` |
| 轨迹拖尾（已飞过） | 3 px | `#FF6A13` @ 60% alpha | 向后渐隐 |

**规则：**

- **所有描边线宽 ≥ 2 px**（1 px 仅用于网格、刻度等纯装饰，且在缩放时按 `--ui-scale` 同步放大，最小不低于 1 px）。
- **禁止 1 px 承载任何语义**（1 px 在 6 m 外投影下会消失）。
- 线端统一 `stroke-linecap: round; stroke-linejoin: round;`（SVG）；Canvas 对应 `lineCap='round'; lineJoin='round'`。
- **虚线仅用于"参考/预测/目标"语义**，实线表示"实际/当前"。这条规则全局一致，不得例外。

### 5.3 SVG 缩放与线宽（`vector-effect`）

**问题背景**：SVG 箭体的用户单位 = **米**，若直接写 `stroke-width: 2`，渲染出来是 **2 米粗**的线。因此所有 SVG 描边**必须**加 `vector-effect="non-scaling-stroke"`，让线宽按屏幕像素解释。

**取舍确认：采用 `non-scaling-stroke`，✅ 认可当前实现。** 理由：

- 火箭的显示尺度跨度极大（整箭可见时 zoom ≈ 10 px/m，放大看逃逸塔时 zoom > 100 px/m）。
- 若放弃 `non-scaling-stroke`，**小尺度下线条会细到消失**——这是致命的（`§5.2` 的 2 px 下限就是为了防这个）；
- 而大尺度下线偏细只是"蓝图感减弱"，是观感问题，不是可用性问题。
- **两害相权，保下限优先。**

**副作用补偿：按 zoom 分档提升线宽**（不改 `vector-effect`，只切 CSS 变量，改动极小）：

| 相机 zoom（px/m） | 典型场景 | 结构线 `.rk-body` / `.rk-fair-body` / `.rk-nozzle` | 细节线 `.rk-band` / `.rk-truss` | 触发 class |
|---|---|---|---|---|
| < 25 | 整箭可见、起飞远景 | **2 px** | 1 px / 2 px | （默认） |
| 25 – 60 | 放大看某一级、发动机 | **2.5 px** | 1.5 px / 2.5 px | `.rk-zoom-2` |
| > 60 | 放大看逃逸塔、喷管细节 | **3 px** | 2 px / 3 px | `.rk-zoom-3` |

```css
/* 默认（< 25）已在各元素上写死；以下两档为放大时的补偿 */
.rk-zoom-2 .rk-body,.rk-zoom-2 .rk-fair-body,.rk-zoom-2 .rk-nozzle{stroke-width:2.5}
.rk-zoom-2 .rk-band{stroke-width:1.5}
.rk-zoom-2 .rk-truss{stroke-width:2.5}

.rk-zoom-3 .rk-body,.rk-zoom-3 .rk-fair-body,.rk-zoom-3 .rk-nozzle{stroke-width:3}
.rk-zoom-3 .rk-band{stroke-width:2}
.rk-zoom-3 .rk-truss{stroke-width:3}
```

**实现要求**：

1. JS 在 zoom 跨档时给 SVG 根元素切换 class（**加 32 px/m 的滞回区间**，避免在阈值附近反复抖动）。
2. 分档切换配 200 ms `stroke-width` 过渡，避免跳变。
3. **分档只影响 SVG 箭体层**，HUD 与 UI 不参与（UI 缩放由 `--hud-scale` 独立控制）。
4. 逃逸塔桁架 `.rk-truss` 在此规则下**永远 ≥2 px**，满足 `asset-spec` §1.3「禁止 <2 px」的要求。

## 7. 动效原则

### 7.1 时长与缓动

| 动效类型 | 时长 | 缓动曲线 | 说明 |
|---|---|---|---|
| 微交互（按钮按下、悬停） | **120 ms** | `cubic-bezier(0.4, 0, 0.2, 1)` | standard |
| 状态切换（颜色、图标、进度） | **200 ms** | `cubic-bezier(0.4, 0, 0.2, 1)` | — |
| 面板 / 卡片入场 | **240 ms** | `cubic-bezier(0.2, 0, 0, 1)`（decelerate） | 位移 16 px + 淡入 |
| 讲解浮层入场 | **320 ms** | `cubic-bezier(0.2, 0, 0, 1)` | 位移 16 px + 淡入 |
| 讲解浮层退场 | **200 ms** | `cubic-bezier(0.4, 0, 1, 1)`（accelerate） | — |
| 成就解锁弹出 | **400 ms** 进 + 停留 **3500 ms** + **200 ms** 退 | 进入带 120 ms 弹性回弹（scale 1.0→1.08→1.0） | 全程 ≤4.1 s，不打断操作 |
| 数值滚动 tween | **300 ms** | `cubic-bezier(0.4, 0, 0.2, 1)` | **禁止每帧硬跳**（投影下会闪） |
| 分离动画 | **600–900 ms** | 线性位移 + decelerate 旋转 | 分离是教学重点，要"看得清" |
| 尾焰扰动 | 循环 | 正弦（见 7.4） | — |

**禁止的缓动**：`ease-in-out` 弹跳、`elastic`、`bounce`（教学场景显得轻佻，且大屏下放大不适感）。

### 7.2 动效使用场合

| 场合 | 允许 | 禁止 |
|---|---|---|
| 数值变化 | 数字 tween 300 ms、量条填充 | 每帧硬跳、数字翻滚器 |
| 状态变化 | 颜色过渡 200 ms + 图标过渡 | 闪烁循环 |
| 新元素出现 | 淡入 + 上移 16 px | 从屏幕外飞入、旋转入场 |
| 元素移除 | 淡出 + 下移 8 px | 爆炸碎裂、缩放消失 |
| 告警 | **2 Hz 闪烁 × 3 次后转常亮** + 边框加粗 | 无限闪烁、全屏红闪 |
| 相机跟随 | 阻尼跟随（系数 0.08–0.12） | 屏幕震动、视差抖动、自动旋转 |

### 7.3 晕动症与大屏观感（前庭安全）

| 限制项 | 硬阈值 | 理由 |
|---|---|---|
| **全屏平移 / 旋转 / 缩放** | **禁止**（相机除外，见下） | 前庭冲突主因 |
| 相机缩放变化率 | ≤ 0.5× / 秒 | 防止"拉镜头晕" |
| 相机平移速度 | ≤ 屏幕宽 30% / 秒 | — |
| 屏幕震动（撞击） | 单次 **150 ms**、幅度 ≤ 屏幕 **2%**、频率 ≤ 2 Hz | 仅允许 1 次，不做循环 |
| 全屏高对比闪烁面积 | ≤ 屏幕 **25%** | 光敏癫痫阈值（WCAG 2.3.1） |
| 任何闪烁频率 | **≤ 3 Hz** | WCAG 2.3.1 硬指标 |
| 背景视差层 | 允许（星空 ≤ 2 层，位移差 ≤ 1.5×） | 深度感，位移差过大会晕 |
| 粒子数量 | 按帧率自适应：<50 fps 减半，<35 fps 关闭 | 大屏投影帧率有限 |

### 7.4 尾焰扰动（唯一允许的循环动效）

```
// Canvas 逐帧：低频正弦扰动，禁止高频噪声
ω   = 7.0 rad/s          // 角频率，范围 6–9
amp = 0.06 * flameLength // 振幅，禁止 > 0.10
x_offset(y, t) = sin(t * ω + y * k) * amp * (y / flameLength)   // k ≈ 0.15
// reduced-motion 时 amp = 0，仅保留静态渐变
```

### 7.5 减少动效（Motion 开关）

| 档位 | 触发 | 关闭项 | 保留项 |
|---|---|---|---|
| **完整** | 默认 | — | 全部 |
| **精简** | `prefers-reduced-motion: reduce` 自动命中，或手动选择 | 尾焰扰动、粒子、相机阻尼（改瞬移）、面板入场位移（改为纯淡入 120 ms）、数字 tween（改跳变）、成就弹跳 | 颜色过渡、进度填充、告警提示（改静态描边） |
| **关闭** | 手动选择 | 上述全部 + 所有淡入淡出 | 仅状态色瞬变、进度条瞬变 |

**规则**：首次启动时读取 `prefers-reduced-motion`，若为 `reduce` 则默认进入"精简"并弹出一次性提示（可改回）。设置项在演示模式控制条与挑战模式设置面板均常驻可见。

## 8. 视觉锚点落地（5 条）

这 5 条是"别人一眼认出这是我们家产品"的特征，实现时必须全部做到。

### 锚点 1 · 蓝图网格底 + 细描边

所有视图最底层是 **32 px 工程蓝图网格**（浅色 `#E3E9EF` / 深色 `#1B2A3D`，1 px，含每 4 格加深一档的主网格）。所有元素对齐网格，标注线平行于网格轴。
→ 瞬间建立"工程图纸"语境，也是所有布局的对位基准。

### 锚点 2 · 火箭居左三分线、竖直、整箭可见

主视图构图固定：**火箭轴心位于画面宽度左侧 1/3 处（33.3%）**，箭体竖直，起飞前整箭完整可见；右侧 2/3 留给 HUD、轨道图与讲解浮层。
→ 学生每次抬头都能在同一位置找到火箭，教师讲解时视线路径稳定。**禁止把火箭居中**（会挤掉数据区，且不符合测控台构图）。

### 锚点 3 · 橙 = 能量

**只有"推进/燃烧/节流/Δv/动压峰值"允许用橙 `#FF6A13`。** 全画面橙色出现面积 ≤ 8%。
→ 一旦画面出现大面积橙，即代表高节流或高动压，形成条件反射。**禁止用橙做标题、按钮、背景装饰。**

### 锚点 4 · 只有等宽数字 + 量条，没有拟物仪表盘

**弃用**一切拟物罗盘、指针式仪表、旋钮、人工地平仪。姿态用数字（俯仰/偏航/滚转，等宽）+ 简化的姿态球（线框，非拟物）；所有量用 **数字 + 10 px 高条形量**。
→ 投影下拟物的细刻度会糊成一片；数字 + 量条远距可读且信息密度高。

### 锚点 5 · 底部横贯事件时间线

发射后的关键事件（助推分离 → 一级分离 → 整流罩抛除 → 二级关机 → 入轨）作为**固定在画面底部的水平时间轴**，实心填充表示已完成进度，事件点为圆形标记 + 文字标签。
→ 学生随时知道"任务进行到哪一步"，教师可指着时间线回溯讲解。**禁止使用自动滚动的动画进度条。**

## 9. 禁止事项

### 9.1 技术红线

1. **禁止任何外部资源**：图片文件（png/jpg/svg 文件）、字体文件（woff/ttf/otf）、CDN、网络请求、npm 依赖。所有资产必须代码内绘制（Canvas 绘制指令 / 内联 SVG / CSS）。
2. **禁止裸 hex 值**：代码中所有颜色必须引用主题变量 / 主题常量对象。
3. **禁止非等宽字体排布会变化的数字**。
4. **禁止 12 px 以下字号**；实际下限为 18 px。
5. **禁止毛玻璃（`backdrop-filter: blur`）**：投影下糊成一团，且大屏性能差。需要半透明面板时用高不透明度纯色（≥0.94）+ 1 px 边框。

### 9.2 视觉红线

6. **禁止卡通化、拟人化**：火箭与飞船不得有眼睛、笑脸、表情、拟人手脚。
7. **禁止纯装饰性渐变、阴影、光晕、辉光、噪点纹理**。唯一允许的渐变是**功能性渐变**：大气层、尾焰、星空背景、量条填充。
8. **禁止阴影（`box-shadow` / `drop-shadow`）承载语义**；如需分层，用边框 + 底色差，不用投影。
9. **禁止同屏出现超过 3 种强调/语义色**（品牌橙 + 至多 2 种语义色）。

### 9.3 内容红线

10. **禁止出现其他国家/机构的火箭型号、外形特征或涂装文字**。仅使用中国载人登月构型：**长征十号运载火箭 + 梦舟载人飞船**。
11. **禁止出现国旗、国徽、军徽、党徽、政治标识、标语口号、领导人形象或语录。**
12. **禁止涉政、涉军、涉密表述**。内容聚焦工程与科学：物理原理、构型设计、飞行程序、轨道力学。
13. **禁止虚构或夸大技术参数**。所有数据以公开资料为准，无法核实的用"约"标注。

### 9.4 可访问性红线

14. **禁止纯靠颜色传达状态**（必须颜色 + 形状/文字/位置 至少 2 重编码）。
15. **禁止 `outline: none` 而不提供替代焦点样式**。
16. **禁止 > 3 Hz 闪烁、全屏旋转/缩放动效、>25% 屏幕面积的高对比闪烁。**
17. **禁止在演示模式（投影）下提供深色主题选项。**
