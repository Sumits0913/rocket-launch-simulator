## 1. 背景（Context）

本项目的质量标准第一条是「**物理正确性 > 视觉华丽**」，并且：

- 用户决策 #3 要求**时间线拖拽到任意时刻回溯**，实现方式是确定性重放（ADR-002）；
- 确定性重放成立的必要条件是：**积分结果只由「初始状态 + 输入序列」决定，与帧率、机器、显示器刷新率完全无关**。

因此，积分器的选型的首要目标不是"精度最高"，而是"**确定性 + 精度足够**"。

## 2. 决策（Decision）

采用 **RK4（四阶龙格–库塔）定步长积分**，配合：

1. **分区步长** —— 按飞行阶段切换步长；
2. **滞环（hysteresis）** —— 防止在分区边界上高频抖动；
3. **固定步长累加器** —— 把真实帧率与积分步长彻底解耦。

### 2.1 为什么是 RK4 而不是别的

| 候选 | 评估 | 结论 |
|---|---|---|
| **欧拉法（显式）** | 一阶精度。在大气段 dt=0.02 s 下，重力转弯的那 170 s 会累积出**几十米每秒**的误差，Δv 恒等式残差会大到没法看。 | 否决 |
| **半隐式欧拉 / Verlet** | 二阶，且对保守系统有辛结构。但本项目有强非保守项（推力、阻力），辛优势用不上。 | 否决 |
| **RK2（中点法）** | 二阶。精度不够，且相比 RK4 只省 2 次导数求值，而本项目单次导数求值很便宜（14 维、几次查表）。 | 否决 |
| **RK4** | **四阶，单步误差 O(h⁵)**。大气段 h=0.02 s 下，实测 Δv 恒等式残差 **4.9 × 10⁻⁷ m/s**（200 km）/ **1.2 × 10⁻⁶ m/s**（400 km）—— 残差已经到浮点舍入噪声量级，再提高精度没有意义。 | **采纳** |
| **RK45（自适应，如 Dormand–Prince）** | 自适应步长的步长序列**依赖局部误差估计**，而误差估计依赖状态演化路径 —— 只要实现是纯确定性的，它仍然可以是确定性的。**但**它有一个致命问题：步长会随状态连续变化，导致"跨步事件检测"的时刻定位精度不可控，且难以保证两个不同起点的重放落在同一批步上。 | 否决（见 §2.4） |
| **隐式方法** | 需要解非线性方程组（牛顿迭代），迭代次数会随收敛判据浮动，**天然不确定**。 | 否决 |

### 2.2 分区步长

```js
// src/core/constants.js
DT_ATMO:  0.02,   // 大气段（h < 105 km 上行）：需要分辨 Max-Q、跨音速、程序转弯
DT_VAC:   0.25,   // 真空段（有推力）
DT_COAST: 0.50,   // 滑行段 / 停泊（无推力，轨迹是纯二体问题）
```

| 阶段 | 为什么是这个步长 |
|---|---|
| 大气段 **0.02 s** | 动压峰值附近（T+70 s 左右，q ≈ 25.9 kPa）气动参数变化剧烈；跨音速段 Cd 从 0.30 冲到 0.60 再回落，需要足够分辨率。0.02 s 对应 50 Hz，一个跨音速过程（约 20 s）有 1000 个采样点，足够。 |
| 真空段 **0.25 s** | 大气项已归零，状态演化是平滑的（推力 + 平方反比引力）。0.25 s 下 RK4 的局部误差远小于 1 mm/s。 |
| 滑行段 **0.50 s** | 纯二体开普勒运动，RK4 在此步长下数十分钟的位置误差 < 1 m。滑行段是教学价值最高的 3 分钟（用户决策 #7），必须能长跑而不漂移。 |

全任务步数实测：**12516 步（200 km）/ 12595 步（400 km）**。

### 2.3 滞环（为什么不能只用一个阈值）

```js
ATMO_UP:   105000,   // 上行：高度超过 105 km → 退出大气段
ATMO_DOWN:  95000,   // 下行：高度低于 95 km 且动压 > 100 Pa → 重回大气段
ATMO_Q_GATE:  100,   // 动压门槛 Pa（防止在真空里因为 h 抖动误判）
```

若只用单一阈值（如 h > 100 km 退出、h < 100 km 进入），在高度恰好在阈值附近震荡时，**每一步都可能切换分区** —— 步长序列会剧烈抖动，既损失性能（大气段 0.02 s 比真空段 0.25 s 慢 12.5 倍），又会让 Max-Q 附近的积分行为变得难预测。

10 km 的滞环带宽（105 / 95）+ 动压门槛，保证在真实弹道上**分区切换只发生有限次且是单向的**。

### 2.4 固定步长累加器（本 ADR 最关键的一条）

**早期（错误）写法**：

```js
while (remaining > 0) {
  var dt = Math.min(pickStep(), remaining);   // ← 问题在这里
  step(dt);
  remaining -= dt;
}
```

在 60 fps 下，每帧 `remaining = 0.0167 s`，而大气段 `pickStep() = 0.02 s`。于是 `Math.min` 每次都返回 **0.0167** —— **每一个物理步都被截断成帧时间**。积分步长由显示器刷新率决定：

- 144 Hz 显示器 → 步长 0.00694 s；
- 掉到 30 fps → 步长 0.0333 s；
- 切后台再回来 → 一次性追赶上千步，步长完全乱掉。

后果是**同一条输入序列在不同机器上走出不同的弹道**，确定性重放（ADR-002）直接失效。

**正确写法**：

```js
this._acc += dtSim;                       // 帧时间进累加器
while (this._acc > 1e-9 && guard++ < lim) {
  var dt = this.pickStep();
  if (dt > this._acc) { break; }          // 余量不够一个完整步长，留到下一帧
  step(dt);
  this._acc -= dt;                        // 扣的是请求步长，不是实际步长
}
```

这样**步长序列恒为 `pickStep()` 的返回值**，与帧率、与机器完全无关。代价是画面上每帧推进的仿真时间是"量子化"的（大气段以 20 ms 为单位跳），但 20 ms 在视觉上完全不可察觉。

配套措施：

- `dtWall` 在 `main.js` 里被 `Math.min(dtWall, 0.100)` 钳位，防止切后台回来时一次性追赶过多；
- `MAX_STEPS_PER_FRAME = 200` 硬上限，防止极端情况下卡死主线程；
- `seek()` 前调用 `flushAccumulator()`，把残留余量清零，保证重放起点干净。

## 3. 状态向量（14 维）

```js
// src/core/dynamics.js
[0]  x           ECI 位置 X（东）        m
[1]  y           ECI 位置 Y（天顶）      m
[2]  vx          ECI 速度 X              m/s
[3]  vy          ECI 速度 Y              m/s
[4]  pB          单个助推器剩余推进剂     kg
[5]  p1          芯一级剩余推进剂         kg
[6]  p2          芯二级剩余推进剂         kg
[7]  p3          芯三级剩余推进剂         kg
[8]  theta       实际姿态角（一阶滞后后） rad
[9]  dvIdeal     ∫(F/m) dt               m/s
[10] dvGrav      ∫(μ/r²)·sinγ dt         m/s
[11] dvDrag      ∫(D₀/m) dt              m/s
[12] dvSteer     ∫(F/m)(1−cosα) dt       m/s   α  = 推力与【惯性速度】的夹角
[13] dvSteerSelf ∫(F/m)(1−cosα_s) dt     m/s   α_s = 推力与【自速度】的夹角
```

后 5 个是**积分式账本**，不是独立自由度 —— 它们被一起放进 RK4 里积分，好处是**账本与轨迹用同一个积分器、同一套步长**，不存在"轨迹算一遍、账本另算一遍"的口径不一致问题。

### 3.1 为什么有两个转向损失（教学口径，重要）

这是本项目**唯一一处对 `physics.md` §9.1 的有意扩展**，需要向设计侧说明：

- **恒等式口径**（`dvSteer`，index 12）：α 是推力与**惯性速度**的夹角。这是 Δv 恒等式 `v = Δv_ideal − Δv_grav − Δv_drag − Δv_steer + v_rot` 成立所必需的口径。
- **教学口径**（`dvSteerSelf`，index 13）：α_s 是推力与 **v⃗_self = v⃗ − v⃗_rot**（火箭自己挣出来的那部分速度）的夹角。

**为什么需要两套**：起飞瞬间，火箭的惯性速度是 **438 m/s 正东**（地球自转赠送），而推力**垂直向上**，于是 α ≈ 90°。头 30 s 的"转向损失"会积到约 380 m/s，全程约 800 m/s。

这个数在物理上**没有算错**（推力确实没有增加惯性速率），但拿给学生看会被误读成"我们转弯转丢了 800 m/s"——而教科书上这一项只有 **60 m/s 量级**。

实测两个口径：

| 目标 | 恒等式口径 | 教学口径 | 差值 = 自转不对齐项 |
|---|---|---|---|
| 200 km | 804.91 m/s | 81.31 m/s | 723.60 m/s |
| 400 km | 905.84 m/s | 166.85 m/s | 738.98 m/s |

**HUD 上给学生看的是教学口径（81 / 167 m/s），Δv 恒等式用恒等式口径（805 / 906 m/s）。** 两者之差被单列为"自转不对齐"一项，在自检脚本里有一条专门的断言验证这个恒等关系。

## 4. 事件检测

事件（13 个，E0–E12，如助推器分离、抛整流罩、二级关机、滑行段）由**推进剂过零**或**遥测量极值**触发。

**关键做法：跨步线性插值定位过零时刻**（`physics.md` §8.5）。

若不做插值，事件时刻会被量化到步长边界（大气段 20 ms、真空段 250 ms），滑行段 250 ms 的量化误差会明显影响 400 km 任务的精度。

```js
// 推进剂从 p0 > 0 变到 p1 < 0，线性插值定位 p = 0 的时刻
var frac = p0 / (p0 - p1);
var used = dt * frac;          // 本步实际只用了这么多
```

`step(dt)` **返回实际使用的时间**，`advance()` 里累加器扣的是**请求步长**而不是 `used` —— 这个细节保证了步长序列的纯粹性（不被事件打断而改变），同时又让事件时刻精确到插值精度。

Max-Q（E3）用的是**极值检测**：`maxQ.q > 5000`（Pa，剔除起飞瞬间的数值噪声）且当前动压回落到峰值的 99.5% 以下时判定峰值已过。这是一个**滞后触发**，因为峰值时刻只有在看到下降沿后才能确认。

## 5. 大气模型

**US Standard Atmosphere 1976，7 层模型**，覆盖 0–86 km 几何高度，86 km 以上按 **H = 7000 m 指数外推**。

实现（`src/core/atmo.js`）：

- `exact(h)` —— 逐层精确公式（温度梯度层 / 等温层分开处理），是**权威实现**；
- `at(h)` —— 预计算 0–100 km、100 m 步长的查找表 + 线性插值，是**运行时使用的版本**；
- `selfTest()` —— 自检函数，对比查表与精确公式。

**为什么查表**：`deriv()` 每个 RK4 子步都要算一次大气，一次全任务 12516 步 × 4 子步 ≈ 5 万次调用。查表把每次调用从"多次 `Math.pow` + 分支"降到"一次索引 + 一次线性插值"。

**查表精度**：实测查表 vs 精确公式最大相对误差 **0.0000%**（在 0 m 处），远低于 1% 的容差。

### 5.1 ⚠ 几何高度 vs 位势高度（一个必须说清楚的坑）

常被引用的 US76 值是**位势高度（geopotential）**下的，本项目用的是**几何高度（geometric）**。两者关系 `H = z·r/(r+z)`，r = 6356.766 km。

在 50 km 处，位势 50 km 对应几何 **50.393 km**；25 km 位势对应几何 **24.902 km**。这解释了为什么：

| 高度 | 本项目（几何） | 常引用值（位势 25/50 km） | 差异来源 |
|---|---|---|---|
| 25 km | 3.9466 × 10⁻² | 4.008 × 10⁻² | **不是误差**，是高度定义不同 |
| 50 km | 9.7756 × 10⁻⁴ | 1.0269 × 10⁻³ | 同上 |

**这不是实现错误**。物理自检的 B 节拿 `Atmo.REF`（几何高度表）做对比并打印了说明。若美术或设计侧拿位势高度的表来对，会对不上 —— 请以本项目的几何高度表为准。

## 6. 引力与地球自转

- **引力**：平方反比 `g = μ / r²`，μ = 3.986004418 × 10¹⁴ m³/s²。**不用常数 g**，因为滑行段要跑 400 km 高度、数百公里水平距离，常数 g 会产生可观的误差。
- **地球自转**：**不作为力项**，而是作为**初速**处理 —— 发射点的惯性初速 `v_rot = ω · R₀ · cos φ = 438.056 m/s`（实测值，φ = 19.6°）。这是物理上等价且数值上更干净的做法（不在 `deriv()` 里引入科里奥利/离心项）。

## 7. 坐标系

**2D 平面 ECI**：X = 东，Y = 天顶。发射点 `(0, R₀)`。

轨道倾角由 `cos i = cos φ_lat · sin ψ` 给出，ψ 为发射方位角（正东 ψ = 90°）→ **i = φ_lat = 19.6°**，实测 **19.614°**。

2D 而非 3D 的选择：本项目只做「发射 → 入轨」，全程在一个平面内，2D 足够且**状态维数减半、性能翻倍、代码复杂度大幅下降**。若将来要做变轨/交会，需要升到 3D —— 届时需重开 ADR。

## 8. 验证

`tests/physics-audit.js`（60 项断言，全部通过）中与本 ADR 直接相关的：

| 检查 | 实测 |
|---|---|
| Δv 恒等式残差（200 km） | **4.879 × 10⁻⁷ m/s** |
| Δv 恒等式残差（400 km） | **1.176 × 10⁻⁶ m/s** |
| 积分式 ∫(F/m)dt vs 分段火箭方程 | 0.330% / 0.278% |
| 两个转向口径之差 = 自转不对齐（恒等） | ✓ |
| 查表 vs 精确公式 | 0.0000% |
| 实时推进 vs 裸重放末态差（确定性） | **0.000e+0** |
| 两种推进方式步数一致 | 12516 vs 12516 |

**残差 10⁻⁷ 量级的含义**：这不是"积分误差小"，而是"积分误差已经小于 IEEE 754 双精度在 10⁴ 量级数值上的舍入噪声"。也就是说，**继续减小步长不会让结果更"准"，只会更慢**。当前的步长选择是精度与性能的正确平衡点。

## 9. 后果与风险

| 风险 | 等级 | 缓解 |
|---|---|---|
| 有人把 `advance()` 改回"按帧时间截断步长"的写法 | 高 | `sim.js` `advance()` 上方有 6 行加粗注释说明为什么必须累加；改了物理自检 I 节会立刻失败 |
| 有人引入自适应步长 | 高 | 需要在 `pickStep()` 里保证步长只依赖状态不依赖墙钟；改动必须重跑自检 I 节 |
| 大气表与位势高度表混用 | 中 | §5.1 已写明；`Atmo.REF` 注释里也标注了"几何高度" |
| 滑行段长时间积分漂移 | 低 | 实测 200 km 滑行 102 s / 400 km 滑行 320 s，入轨精度 e < 5 × 10⁻⁴，无漂移 |
| `MAX_STEPS_PER_FRAME = 200` 在极端倍速下不够 | 低 | 倍速上限受 UI 限制；即使截断也只是"这一帧少推进一点"，下一帧继续，不影响正确性 |
