# 火箭发射模拟器 · 架构说明

> **版本**：v1.0（2026-09-01）
> **范围**：仅「发射 → 入轨」。不含地月转移、环月、着陆、返回（那部分属于既有的《中国载人登月任务互动课堂 V4》，本项目不读取、不复制、不修改 V4 的任何文件）。
> **技术负责人**：程基岩（RL-03）
> **读者**：接手维护的工程师。本文假设你懂 JS，但**不假设你懂火箭**。

---

## 0. 三句话概括

1. **零依赖单页应用**，双击 `index.html` 就能玩。因为要跑在 `file://` 下，**不能用 ES Module**（见 ADR-001）。
2. **物理是确定性 RK4 定步长积分**，所以时间线拖拽回溯用**重放**而不是**快照**（见 ADR-002 和 ADR-004）。
3. **渲染分三层**：SVG 画箭体，Canvas 画尾焰和背景，DOM+CSS 画 HUD（见 ADR-003）。

## 2. 分层与依赖方向

```
┌──────────────────────────────────────────────────────────┐
│  index.html      装配 + 全部 CSS 变量 + 脚本加载顺序        │
└────────────────────────┬─────────────────────────────────┘
                         │
┌────────────────────────▼─────────────────────────────────┐
│  src/app/        应用层：main / modes / hud / render /     │
│                  timeline / input / replay / score /      │
│                  svg-rocket / a11y / config               │
│                  （碰 DOM，浏览器专用）                     │
└────────────────────────┬─────────────────────────────────┘
                         │
┌────────────────────────▼─────────────────────────────────┐
│  src/core/       物理内核：sim / steering / dynamics /     │
│                  vehicle / orbit / atmo / constants       │
│                  （纯计算，不碰 DOM，Node 可直接 require）  │
└──────────────────────────────────────────────────────────┘
```

**依赖严格单向：`app → core`，反过来不成立。** 这条不变量保证了物理内核可以脱离浏览器被测试。

### 2.1 为什么这样分层

`src/core/` 下的 7 个文件**全部不引用 `window`、`document`、任何 DOM API**。它们用 UMD 包装，在 Node 下可以直接 `require`：

```js
var Sim = require('./src/core/sim.js');    // 真的可以
```

这使得 `tests/physics-audit.js` 可以**直接跑真实仿真代码做断言** —— 不是跑一份"测试用的简化模型"，而是跑**给玩家用的那份代码**。这是本项目"物理正确性 > 视觉华丽"质量标准的工程保障。

## 3. 模块挂载方式（ADR-001）

**禁止 `<script type="module">` 和 `import` / `export`。** 原因：`file://` 协议下模块的 origin 是 `null`，CORS 会直接拦截。

改用 UMD 包装 + 全局命名空间：

```js
;(function (root, factory) {
  var mod = factory();
  if (typeof module === 'object' && module.exports) {
    module.exports = mod;              // Node：给测试脚本 require
  }
  root.RK = root.RK || {};
  root.RK.Atmo = mod;                  // 浏览器：挂到全局命名空间
})(typeof globalThis !== 'undefined' ? globalThis : this, function () {
  'use strict';
  /* ... 实现 ... */
  return { at: at, exact: exact, selfTest: selfTest, REF: REF };
});
```

**全局只占用 `window.RK` 一个符号**，其余 18 个模块全部收敛其下。

`index.html` 里按依赖拓扑序手写 `<script src>` 列表，分 5 层并附注释。**新增模块时按层插入即可。**

```

   玩家按键  ───▶ │  input.js    │ ──▶ 输入指令（阶跃 + 时刻）
                 └──────────────┘            │

                 ┌──────────────────────────────────────────┐

                 │   ├─ 录制输入轨道 track[]                │
                 │   ├─ 每 5 s 存一个精确检查点（纯性能）    │

                 └───────────────┬──────────────────────────┘
                                 │ sim.tele / sim.y / sim.events
             ┌───────────────────┼───────────────────┐
             ▼                   ▼                   ▼
     ┌───────────────┐  ┌────────────────┐  ┌──────────────┐
     │ render.js     │  │ svg-rocket.js  │  │ hud.js       │
     │ Canvas L0–L2  │  │ SVG L3         │  │ DOM L4       │
```

## 5. 关键设计决策一览

| 决策 | 位置 | 一句话理由 |
|---|---|---|
| 不用 ES Module | ADR-001 | `file://` 下 CORS 拦截模块加载 |
| 时间线拖拽用重放不用快照 | ADR-002 | 快照要插值 → 状态不一致；重放逐位相同且只存输入（极小） |
| 箭体用 SVG、尾焰用 Canvas | ADR-003 | SVG 任意缩放锐利 + 主题零重绘 + 可被屏幕阅读器读；尾焰需要 `lighter` 合成，SVG 不支持 |
| RK4 定步长 + 累加器 | ADR-004 | 四阶精度足够（残差 10⁻⁷）；累加器把步长与帧率解耦，是确定性的前提 |
| 2D 平面 ECI 而非 3D | `dynamics.js` | 发射→入轨全程在一个平面内，2D 状态维数减半、复杂度大降 |
| 地球自转作初速不作力 | `constants.js` | 物理等价，数值更干净（不在 `deriv()` 引入科里奥利/离心项） |
| 地球按可见弧段采样绘制 | `render.js` | 半径 6.4e7 px 的圆会击穿光栅化器 |
| 两个转向损失口径 | `dynamics.js` | 恒等式口径 805 m/s 不能给学生看（教科书是 60 m/s 量级）；教学口径 81 m/s 才对 |
| 严重度用形状边数编码 | `a11y.js` | 只用颜色区分对色弱用户无效；圆=正常、三角=注意、菱形=警告、六边形=危险 |
| HUD 数字 10 Hz + 300 ms 补间 | `hud.js` | 60 Hz 跳数字读不出来；补间让变化可跟随 |

## 6. 参数中枢：`src/core/constants.js`

**所有物理参数只在这个文件里写一次。** 其他文件一律引用，不得硬编码数字。

参数按来源打标签，便于设计侧和讲解时追溯：

| 标签 | 含义 | 例子 |
|---|---|---|
| 【公开】 | 来自公开资料 | GLOW 2187 t、单台 YF-100K 1250 kN |
| 【推导】 | 由公开量算出 | 起飞推重比 1.224、Δv 预算 |
| 【近似】 | 数量级正确、数值可调 | Cd₀ 随马赫数曲线、姿态一阶滞后时间常数 |
| 【游戏】 | 纯教学/手感参数，无物理依据 | 评分权重、成就阈值、相机缩放率 |

### 6.1 锁定参数（已三重校验，不要改）

| 参数 | 值 |
|---|---|
| 构型 | 三级半；助推器 2 × **5.0 m 直径（与芯级同径）** ← 长十与长五的关键识别特征 |
| 一级发动机 | **21 台 YF-100K**（3 模块 × 7 台），单台 1250 kN |
| 起飞推力 | **26 250 kN（2677 tf）** |
| GLOW | **2187 t** |
| 起飞推重比 | **1.224**（= 26 250 000 / (2 187 000 × 9.80665) = 1.223939，全项目口径已统一，见 §9 D1） |
| 全长 / 芯级直径 | 92.5 m / 5.0 m（长细比 18.50 D） |
| 三级满载总理想 Δv | **12 316 m/s**（文档写 12 263，见 §9 偏差 D2） |
| LEO 入轨需求 | 9068 m/s |
| 剩余可支撑 TLI | **3250 m/s**（公开 TLI 需求 3.1–3.2 km/s，对得上） |
| 地球自转赠送初速 | 438.056 m/s（φ = 19.6°） |
| 轨道倾角 | 19.614° |

### 6.2 两个目标轨道的难度参数是**分别调校**的

`TARGETS` 里 200 km 和 400 km **各有一套**参数（`cPitch` 程序转弯系数、`thetaFloor` 俯仰下限、`coastMax` 滑行上限、`s3Budget` 三级推进剂预算、以及完美/成功/软失败的近远地点判定区间）。

**不要试图用一套参数覆盖两个目标** —— 400 km 需要更平缓的转弯（cPitch 2.65e-5 vs 3.30e-5）和更长的滑行（400 s vs 130 s）。

## 8. 性能

### 8.1 时间线拖拽（用户决策 #3 的快算性能问题）

实测（`tests/physics-audit.js` 第 I 节，Node v22.22.2，200 次随机拖拽）：

```
拖拽 200 次：平均 0.046 ms，中位 0.021 ms，P95 0.184 ms，最坏 0.319 ms
全任务裸重放（无检查点）：8.31 ms / 12516 步
```

| 场景 | 耗时 | 占 60 fps 单帧预算（16.7 ms） |
|---|---|---|
| 典型拖拽（中位） | 0.021 ms | 0.13% |
| 最坏拖拽 | 0.319 ms | **1.9%** |
| 极端：从 t=0 裸重放全程 | 8.31 ms | 50% |

**结论：拖拽不需要防抖，也不需要节流。** `timeline.js` 头部注释里写明。理由：

1. 每 5 s 一个精确检查点，最坏只需重算 5 s 仿真时间（约 250 步）；
2. 加防抖会让拖拽手感变黏，教学演示时是明显缺陷；
3. 加节流会把 0.3 ms 的延迟变成最多 16 ms，是纯负优化。

**检查点只影响性能，不参与正确性** —— 删掉全部检查点从 t=0 裸重放，结果与实时推进**逐位相同**（实测末态差 `0.000e+0`）。

### 8.2 60 fps 的保障措施

| 措施 | 位置 |
|---|---|
| DPR 封顶 2 | `render.js` `resize()` |
| 星空生成一次后缓存在离屏 canvas（600 图元，浅色主题跳过） | `render.js` `_starfield()` |
| 地球只采样可见弧段（不是 6.4e7 px 的圆） | `render.js` `_earthPath()` |
| SVG 每帧只改 8 个 `transform` + 2 个 `class` | `svg-rocket.js` `update()` |
| 分离动画交给 GPU 合成（纯 transform） | `svg-rocket.js` |
| 尾焰逐帧扰动在 `reducedMotion` 下完全关闭 | `render.js` `_drawPlume()` |
| HUD 数字 10 Hz 刷新 + 300 ms 补间（不是 60 Hz） | `hud.js` `RateLimiter(10)` / `Tween(0, 300)` |
| `dtWall` 钳位 100 ms + `MAX_STEPS_PER_FRAME = 200` | `main.js` / `constants.js` |
| 大气查表（0–100 km，100 m 步长）代替逐次精确公式 | `atmo.js` |

## 9. ⚠ 四处文档/参数偏差（需要 team-lead 定夺）

### D1. ✅ 已修复（2026-09-02）：起飞推重比口径统一为 1.224

- 精确算式：`26 250 000 / (2 187 000 × 9.80665) = 1.223939`
- 原状态：`asset-spec.md` §1.1 写 1.225（对应 GLOW 约 2185 t），与精确值差 0.09%
- **处理**：全项目统一为 **1.224**。已同步 `design/art/asset-spec.md` §1.1 与 §7 待确认项表、
  `src/app/hud.js` 核验面板、`src/app/modes.js` E1 教学文案、`src/core/constants.js`
  `SOURCES.TW_RATIO`。海平面大气密度 ρ₀ = 1.225 kg/m³ 与此无关，保持不动。
- **回归防线**：`tests/physics-audit.js` A 节断言收紧为 `near(tw, 1.224, 0.001)`（原 ±0.002），
  实测偏差 6.1e-5，容差仍有 16 倍余量。

### D2. 总 Δv 12 263 vs 实测 12 316 m/s

- **根因**：`design/gdd/vehicle.md` §4.2 表 A 的 `m_end` 写成 627.1 t，正确值应为 **618.1 t**
- `627.1 = 2187 − 1040 − 520`，**漏减了 9 t 的逃逸塔**
- 修正后 A 段 Δv 由 4030 → 4077 m/s，合计由 12 263 → **12 316 m/s**
- 连带影响：剩余可支撑 TLI 的 Δv 由 3195 → **3250 m/s**（仍在公开值 3.1–3.2 km/s 的合理上沿）
- **建议**：`vehicle.md` §4.2 表 A 的 `m_end` 改为 618.1 t，并把总 Δv 改为 12 316

### D3. 标准档三级关机的口径冲突

- 用户决策 #6：**硬核档手动，标准档自动**
- `design/gdd/modes.md` §2.6：标准档 = 手动关机，只有演示档自动
- **本项目按用户决策实现**（`DIFFICULTY.normal.autoCutoff3 = true`），同时在设置面板留了 `manualCutoff3` 开关作为逃生舱，方便改回 GDD 口径
- **需 design-strategist 确认**，并同步修订 `modes.md` §2.6

### D4. 几何高度 vs 位势高度（不是错误，但会影响对表）

- 本项目用**几何高度**实现 US76；常被引用的 25 km = 4.008e-2、50 km = 1.0269e-3 是**位势高度**下的值
- 位势 25 km 对应几何 24.902 km，位势 50 km 对应几何 50.393 km
- 高空出现 1.5%–5% 差异的**唯一原因**就是这个，不是实现错误
- **提醒美术/设计侧**：拿外部大气表对数据时请使用几何高度表（`atmo.js` 里的 `Atmo.REF`）

## 10. 可访问性

| 需求 | 实现 |
|---|---|
| 严重度不能只靠颜色 | `a11y.js` `SEV`：圆(1边) = 正常、三角(3边) = 注意、菱形(4边) = 警告、六边形(6边) = 危险。HUD 上数值旁有形状标记 |
| 数字必须等宽 | 全部 HUD 数字 `font-variant-numeric: tabular-nums` + 等宽字体 + 固定小数位 |
| 数字不能跳太快 | `RateLimiter(10)` 10 Hz 刷新 + `Tween(0, 300)` 300 ms 补间 |
| 前庭安全 | 抖动 ≤ 6 px、≤ 2 Hz（`a11y.js` `shake()`），`reducedMotion` 下关闭 |
| 光敏安全 | 闪光有渐变爬升，不做硬切（`a11y.js` `flashAlpha()`） |
| 屏幕阅读器 | 箭体是 SVG DOM 可挂 `aria-label`；时间线是 `role="slider"`；HUD 读数有 `aria-live` |
| 字号可调 | 设置面板字号开关 → 改一个 CSS 变量，DOM 全部跟着变 |

## 12. 已知的"最容易坏"的两处

### R1. 固定步长累加器（高危）

`sim.js` 的 `advance()`。**如果有人把它改回"按帧时间截断步长"的写法**（看起来更"平滑"、更"省事"），确定性会立刻失效，时间线拖拽会开始漂移，而**表面上程序看起来完全正常** —— 这是最危险的失败模式：静默错误。

- 防护：`advance()` 上方有 6 行加粗注释说明为什么必须累加
- 检测：物理自检 I 节（实时推进 vs 裸重放末态差）会立刻失败
- **验证程度**：已通过。实测末态差 `0.000e+0`，步数一致（12516 vs 12516），7 个采样点的 `seek()` 全部逐位一致

### R2. Canvas 与 SVG 的调色板重复维护（中危）

`render.js` 的 `THEME` 对象和 `index.html` 的 CSS 变量 `--rk-*` 是**两份独立维护的色值**。浏览器限制：Canvas 读不到 CSS 变量，无法避免。

- 后果：改配色时只改一处 → 出现"箭体是新的蓝、尾焰是旧的蓝"
- 缓解：已在 `render.js` `THEME` 上方写明"与 art-bible 对齐，改动需同步两处"
- **验证程度**：已人工核对两处色值当前一致；**未做自动化校验**（Color 值无法在 Node 下比对 CSS 变量，需要人工或加 DOM 测试）
- **建议**：若美术后续改配色，请务必同时改这两处

## 14. 给维护者的三条忠告

1. **改物理参数只改 `constants.js`**，别在其他文件里写数字。
2. **改积分器后必须重跑 `tests/physics-audit.js`** —— 尤其是 I 节（确定性）。物理正确性靠这个脚本兜底。
3. **不要用 `import` / `export`** —— 会直接让程序在 `file://` 下打不开，而"双击即玩"是给科技馆辅导员的第一承诺。理由见 ADR-001，`index.html` 顶部也有加粗注释。
